\section{Descripción detallada de componentes del sistema SGH}

\subsection{Aplicación Web (Next.js)}
Interfaz principal para administración del sistema, desarrollada con Next.js 13 y Tailwind CSS. Incluye:
\begin{itemize}
\item Dashboard administrativo con métricas en tiempo real
\item Formularios reactivos para gestión de entidades
\item Visualización de horarios con calendario interactivo
\item Sistema de autenticación integrado
\item Interfaz responsiva para desktop y tablet
\end{itemize}

\subsection{Servidor Backend (Spring Boot)}
API RESTful desarrollada con Spring Boot 2.7 y Java 11. Componentes principales:
\begin{itemize}
\item Controladores REST con validación automática
\item Servicios de negocio para lógica de horarios
\item Repositorios JPA con consultas optimizadas
\item Seguridad JWT con Spring Security
\item Documentación OpenAPI/Swagger
\end{itemize}

\subsection{Aplicación Móvil (React Native)}
Aplicación nativa para Android desarrollada con React Native y Expo. Características:
\begin{itemize}
\item Autenticación segura con JWT
\item Visualización offline de horarios
\item Notificaciones push para cambios
\item Sincronización automática con backend
\item Interfaz optimizada para dispositivos móviles
\end{itemize}

\subsection{Base de Datos (MySQL)}
Esquema relacional optimizado para consultas de horarios:
\begin{itemize}
\item Tablas principales: users, professors, courses, subjects, schedules
\item Relaciones con integridad referencial
\item Índices para rendimiento en consultas complejas
\item Triggers para auditoría automática
\item Soporte para transacciones ACID
\end{itemize}

\subsection{Infraestructura de Despliegue}
Configuración Docker para entornos consistentes:
\begin{itemize}
\item Contenedores separados para cada servicio
\item Docker Compose para orquestación local
\item Volúmenes para persistencia de datos
\item Redes seguras entre contenedores
\item Configuración de nginx como proxy reverso
\end{itemize}

\section{Algoritmos de Generación de Horarios}

\subsection{Algoritmo Principal: Backtracking con Heurísticas}
Implementación de búsqueda con poda para asignación óptima:
\begin{itemize}
\item Exploración sistemática del espacio de soluciones
\item Validación incremental de restricciones
\item Heurísticas para priorización de asignaciones
\item Caché de resultados parciales
\end{itemize}

\subsection{Restricciones Implementadas}
\begin{itemize}
\item Disponibilidad horaria de profesores
\item Capacidad máxima de aulas
\item Prerrequisitos entre asignaturas
\item Límites de horas diarias/semanaes
\item Conflictos de recursos simultáneos
\end{itemize}

\section{Métricas de Rendimiento Detalladas}

\subsection{Tiempos de Respuesta}
\begin{itemize}
\item APIs REST: <250ms promedio
\item Carga inicial web: <1.8s
\item Generación de horarios: <30s para escenarios medianos
\item Sincronización móvil: <5s
\end{itemize}

\subsection{Cobertura de Pruebas}
\begin{itemize}
\item Backend Java: 75\% unitarias, 80\% integración
\item Frontend React: 70\% unitarias, 75\% integración
\item Móvil React Native: 65\% unitarias, 70\% integración
\item APIs REST: 85\% integración, 75\% E2E
\end{itemize}

\section{Casos de Uso Detallados}

\subsection{Caso de Uso 1: Generación de Horarios Semestrales}

\textbf{Actor Principal}: Administrador académico

\textbf{Precondiciones}:
\begin{itemize}
\item Base de datos poblada con profesores, cursos, asignaturas y aulas
\item Restricciones horarias definidas
\item Período académico configurado
\end{itemize}

\textbf{Flujo Principal}:
\begin{enumerate}
\item Administrador accede al módulo de generación de horarios
\item Selecciona período académico y parámetros de optimización
\item Sistema ejecuta algoritmo de backtracking con validación de conflictos
\item Se presenta horario generado con métricas de calidad
\item Administrador revisa y aprueba o solicita ajustes
\item Horario se publica para consulta de usuarios
\end{enumerate}

\textbf{Flujo Alternativo}:
\begin{itemize}
\item Si hay conflictos irresolubles, sistema sugiere ajustes manuales
\item Usuario puede guardar versiones intermedias del horario
\end{itemize}

\textbf{Postcondiciones}:
\begin{itemize}
\item Horario aprobado disponible para todos los usuarios
\item Métricas de generación almacenadas para análisis
\end{itemize}

\subsection{Caso de Uso 2: Consulta Móvil de Horarios}

\textbf{Actor Principal}: Estudiante/Profesor

\textbf{Precondiciones}:
\begin{itemize}
\item Usuario registrado y autenticado
\item Aplicación móvil instalada
\item Conectividad a internet (opcional para modo offline)
\end{itemize}

\textbf{Flujo Principal}:
\begin{enumerate}
\item Usuario abre aplicación móvil
\item Sistema carga horarios desde cache local o servidor
\item Usuario selecciona vista (diaria, semanal, mensual)
\item Aplica filtros por profesor, curso o asignatura
\item Sistema muestra horario con indicadores visuales
\item Usuario puede exportar o compartir horario
\end{enumerate}

\textbf{Características Especiales}:
\begin{itemize}
\item Sincronización automática cuando hay conectividad
\item Notificaciones push para cambios en horarios
\item Modo offline con datos cacheados
\end{itemize}

\subsection{Caso de Uso 3: Gestión de Conflictos en Tiempo Real}

\textbf{Actor Principal}: Administrador académico

\textbf{Precondiciones}:
\begin{itemize}
\item Horario base generado y aprobado
\item Evento disruptivo identificado (enfermedad docente, cambio de aula)
\end{itemize}

\textbf{Flujo Principal}:
\begin{enumerate}
\item Administrador identifica el conflicto
\item Sistema valida impacto del cambio
\item Algoritmo recalcula asignaciones afectadas
\item Se presentan opciones de resolución
\item Administrador selecciona solución óptima
\item Sistema actualiza horario y notifica usuarios afectados
\end{enumerate}

\textbf{Validaciones}:
\begin{itemize}
\item Verificación de restricciones no violadas
\item Minimización de impacto en otros usuarios
\item Notificación automática a partes interesadas
\end{itemize}

\subsection{Caso de Uso 4: Reportes y Analítica}

\textbf{Actor Principal}: Administrador académico

\textbf{Precondiciones}:
\begin{itemize}
\item Historial de horarios generados disponible
\item Permisos de acceso a datos analíticos
\end{itemize}

\textbf{Flujo Principal}:
\begin{enumerate}
\item Usuario accede al módulo de reportes
\item Selecciona tipo de reporte (utilización de aulas, carga docente, etc.)
\item Define período y filtros
\item Sistema genera reporte con gráficos y métricas
\item Usuario puede exportar a PDF/Excel
\end{enumerate}

\textbf{Reportes Disponibles}:
\begin{itemize}
\item Utilización de recursos por período
\item Distribución de carga horaria por profesor
\item Estadísticas de conflictos resueltos
\item Métricas de rendimiento del sistema
\end{itemize}

\subsection{Diagrama de Despliegue}

El sistema se despliega utilizando Docker Compose con la siguiente arquitectura:

\begin{itemize}
\item \textbf{Contenedor Frontend}: Next.js en Nginx
\item \textbf{Contenedor Backend}: Spring Boot con Tomcat embebido
\item \textbf{Contenedor Base de Datos}: MySQL 8.0
\item \textbf{Contenedor Proxy}: Nginx como reverse proxy con SSL
\item \textbf{Volúmenes}: Persistencia de datos y configuración
\end{itemize}

\subsection{Diagrama de Secuencia - Generación de Horarios}

\begin{enumerate}
\item Usuario solicita generación
\item Backend valida datos de entrada
\item Algoritmo procesa restricciones
\item Base de datos consulta información
\item Sistema genera y valida horario
\item Resultado se almacena y presenta
\end{enumerate}
